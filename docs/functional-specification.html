About this document

This specification records the design of Dependency Tree: how it meets the requirements in the Requirements Catalogue.

Each design decision is a row in a table, with these columns:

Column Meaning
ID For example DES-NAV-001. IDs are never reused.
Design The design decision.
Status Agreed: decided by the product owner, or by the analyst where the choice was delegated. Proposed: recommended by the analyst, awaiting a decision.
Satisfies The requirement IDs the item meets.

The text between the tables explains how they fit together and gives examples.

Data model

Moments and periods

There are two kinds of entry: moments and periods. A period is built from moments, and every dependency links one moment to another (DEC-17). Periods can sit inside larger periods (DEC-21).

ID Design Status Satisfies
DES-DATA-001 Every entry is either a moment, which has a single date, or a period. A period is defined by at least two moments: a start moment and an end moment. It can have any number of moments between them. A period’s dates are the dates of its start and end moments.
Example: the Roman Republic is defined by its founding, c. 509 BCE, and its end, 27 BCE. The writing of the Twelve Tables, c. 450 BCE, is one of the moments between them.		 Agreed REQ-DATA-002
DES-DATA-002 A period that is still going on has a start moment but no end moment yet. Example: “People’s Republic of China, 1949 to present”. Agreed REQ-DATA-006
DES-DATA-003 A moment can belong to more than one period. A period can be part of a larger period. Example: Chinese civilisation contains the Tang dynasty. Agreed REQ-DATA-013, REQ-REL-003
DES-DATA-004 An invention or discovery is a moment on its own, not part of any period: the date it first came into being. It doesn’t need an end date, because it continues to be available. Example: “Lithium-ion battery, 1991”. Proposed REQ-DATA-002
DES-DATA-005 Every entry has a name, alternative names, a description, tags, sources, a stable identifier, an address-friendly name (for example “lithium-ion-battery”), and a Wikidata identifier if it was imported. Proposed REQ-DATA-001, REQ-DATA-003, REQ-DATA-007, REQ-DATA-008, REQ-DATA-012, REQ-CONT-004
DES-DATA-006 Everything in a period falls between its start and end moments, allowing for uncertainty in the dates. This includes the start and end moments of any smaller period inside it. Breaches are listed in the import report. Agreed REQ-DATA-013, REQ-REL-003, REQ-CONT-011
DES-DATA-007 A moment can have a location: a place name such as “Rome” or “China”. Agreed REQ-DATA-009
DES-DATA-008 A period’s start and end moments are real events, never entries made only to mark its dates. So a period has at least two moments: the first of its stops is its start, and the last is its end. There are no stops called “start” or “end”.
Example: the European Theater of World War II starts with the 1939 Invasion of Poland and ends with the German Instrument of Surrender.		 Agreed REQ-DATA-002

Dates

ID Design Status Satisfies
DES-DATE-001 Years are stored as signed astronomical years. 1 BCE is year 0, 2 BCE is year minus 1, and so on. This allows simple comparison and sorting. Users never see this form. Proposed REQ-DATA-004
DES-DATE-002 Each date has a precision. The possible precisions are day, month, year, decade, century, millennium, and multiples of ten thousand years and more for deep history. These are the same precisions that Wikidata uses. Each date also has an “approximate” flag. Proposed REQ-DATA-005
DES-DATE-003 Each date is treated as a range of possible times, from the earliest to the latest:
• “1991”, with year precision, means any time in 1991.
• “19th century” means 1801 to 1900.
• “9 January 2007”, with day precision, means that one day.
• An approximate date widens its range by one unit of its precision on either side. For example, “c. 1450”, with year precision, means 1449 to 1451, and “c. 5th century BCE” means the 6th to the 4th century BCE.		 Proposed REQ-DATA-005, REQ-REL-009
DES-DATE-004 Dates are written and spoken in natural form. Examples:
• “9 January 2007”
• “1991”
• “c. 509 BCE”, spoken as “around 509 BCE”
• “19th century”
• “509 BCE to 27 BCE”, for a period
• “1949 to present”, for a period that is still going on		 Proposed REQ-ANN-008
DES-DATE-005 A date can be in the future, for something planned. Example: “Los Angeles Olympic Games, 14 July 2028 to 30 July 2028”. Agreed REQ-DATA-014
DES-DATE-006 In lists and list labels, dates are shortened by how far they are from today:
• More than 3 years away: the year only, such as “2007”.
• More than 12 months but at most 3 years away: month and year, such as “March 2024”.
• Within 12 months: the full date, as precisely as it is known.
Future dates are treated the same way. A date known only roughly, such as “1970s”, is never made more precise. The summary box and the Space summary give dates in full.		 Agreed REQ-ANN-008, REQ-ACC-015

Relationships

ID Design Status Satisfies
DES-REL-001 Only “depends on” is stored. “Enabled” is the same link read in the other direction. If the laptop depends on the battery, then the battery enabled the laptop. Proposed REQ-REL-001, REQ-REL-008
DES-REL-002 A dependency is rejected only if it certainly happened later than the moment that depends on it. In other words, it is rejected only if the earliest possible date of the dependency is after the latest possible date of the dependent. Where the date ranges overlap, the dependency is allowed.
Example: A, dated c. 1450, depends on B, dated only to the 15th century. B might have come first, so the dependency is allowed.
Example: something dated “1991” can’t depend on something dated “9 January 2007”. The dependency is rejected.		 Agreed REQ-REL-002, REQ-REL-009
DES-REL-004 Containment (“part of”) is separate from dependency. It follows DES-DATA-006, not the predates rule. Proposed REQ-REL-003
DES-REL-005 Circular dependencies are detected when data is imported, and are listed in the report. Proposed REQ-REL-007
DES-REL-006 Dependencies are always between moments. Nothing depends on a period as a whole, and a period depends on nothing as a whole. Example: Roman law depends on the writing of the Twelve Tables, not on the Roman Republic. Agreed REQ-REL-011
DES-REL-007 Where source data links to a period rather than to a moment, the period’s start moment is used. This is to be reviewed against a sample of real data in Phase 0. Agreed REQ-REL-009, REQ-REL-011

Why we call it a tree

From any one moment, looking back through its dependencies, the structure branches out like a tree. That is what the product is named after. (REQ-VIS-005) Strictly, it is a web, because the same entry can be reached by more than one route. The user only ever deals with one entry at a time, so the web never has to be managed as a whole.

Headings serve browse mode instead: the page title, and the current entry’s name. Search and filters, when they come, will have headings too. Agreed REQ-ACC-004, REQ-ACC-015

The tree navigator

The navigator behaves differently on a moment and on a period (DEC-19):

  • On a moment, the user browses its lists, such as Dependencies and Enabled, and presses Enter to go to an entry in one of them.
  • On a period, the user moves through its moments in date order with Up Arrow and Down Arrow, and presses Enter to go into one of them.

Lists on a moment

DES-NAV-001 Each moment presents its relationships as a set of lists, shown as a standard tab control with the active list underneath (DES-SR-006). Agreed REQ-NAV-003
DES-NAV-002 The lists, in order:
1. Dependencies: what this moment needed. (Agreed)
2. Part of: the periods this moment belongs to. A moment can be part of more than one period.

More lists may be added later. Reading the lists from first to last runs from “before”, through “around”, to “after”.		 Agreed REQ-NAV-003, REQ-NAV-023
DES-NAV-003 The Dependencies and Enabled lists are always present, even when empty. The Part of list is only present when it has entries. This means that moving between lists never stops on an empty list that tells the user nothing. Proposed REQ-NAV-003, REQ-ACC-015
DES-NAV-004 Each list remembers its highlighted entry. Until the user moves within the list, this is its first entry. Agreed REQ-NAV-001, REQ-NAV-002, REQ-ACC-015
DES-NAV-005 After moving to another moment, the active list is the kind of list the user just moved through, as long as the new moment has one. Otherwise, it is the Dependencies list.
• After going to a dependency, the Dependencies list is active.
• After going to an enabled entry, the Enabled list is active.		 Agreed REQ-ACC-015
DES-NAV-006 Entries in each list are sorted by date, oldest first. Proposed REQ-ACC-015

While Part of is active, Up Arrow and Down Arrow move through it, and Enter goes to the highlighted larger period. (Proposed, built in Step 0B)		 Agreed in part REQ-NAV-023, REQ-NAV-003

Agreed REQ-NAV-001, REQ-NAV-002, REQ-ACC-015

Announcements

ID Design Status Satisfies
DES-ANN-001 On arriving at an entry, focus enters its new list, and the screen reader reads the list’s label and the highlighted entry. The label names the entry, its shortened date and the list. For example: “Telephone, 1876, Dependencies, list. Electric battery, 1800, 1 of 2.” An empty list’s label ends with “none”. Agreed REQ-ANN-007
DES-ANN-002 Moving within a list moves focus to the entry, which the screen reader reads with its position. For example: “Smartphone, 1994, 3 of 12.” Proposed REQ-ANN-007
DES-ANN-003 Switching list moves focus into the new list, whose label is just the list’s name, followed by the highlighted entry. For example: “Enabled, list. Laptop, 1981, 1 of 8.” An empty list holds one item, “None”, so NVDA+Up Arrow has something to read: “Enabled, list. None.” Enter does nothing on it. Agreed REQ-ANN-007, REQ-ACC-015
DES-ANN-004 There are three verbosity levels:
• Brief: names only
• Normal: as in the examples in this section (the default)
• Full: Normal, plus the first sentence of the description		 Proposed REQ-ACC-010
DES-ANN-005 When filters hide entries, the announcement includes the number hidden. Example: “Dependencies, 3, 2 hidden by filters.” Proposed REQ-ANN-006
DES-ANN-006 A new announcement replaces any announcement that hasn’t been spoken yet. Proposed REQ-ANN-004
DES-ANN-007 When there is nowhere to go, nothing is announced. The only exception is the bump sound (DES-ANN-011). This is to be reviewed after testing, and spoken messages such as “No earlier entries” may be added if silence is confusing. Agreed REQ-NAV-015
DES-ANN-008 Arriving at a period works the same way, through the label of its Moments list. For example: “Information Age, 1970s to present, Moments, list. iPhone, 2007, 5 of 6.” Agreed REQ-ANN-007

Worked examples

The dates and counts in these examples are only illustrations. The words in quotes are what the user hears; the exact wording depends on the screen reader.

Moving between moments. The current entry is the lithium-ion battery. The user arrived from the laptop through the Dependencies list, so the Dependencies list is active (DES-NAV-005).

  1. Ctrl+Right Arrow: “Enabled, 8. Laptop, 1981, 1 of 8.”
  2. Down Arrow twice: “Electric car, 1996, 3 of 8.”
  3. Right Arrow, or Enter: “Electric car, 1996. Enabled, 5.” The Enabled list stays active, so pressing Right Arrow again carries on forward in time.
  4. Backspace: “Lithium-ion battery, 1991. Enabled, 8.” Back where the user was.

Moving into and through a period. The current entry is the writing of the Twelve Tables.

  1. Ctrl+Right Arrow: “Part of, 1. Roman Republic, 509 BCE to 27 BCE, 1 of 1.”
  2. Enter: “Roman Republic, 509 BCE to 27 BCE, 6 moments. Twelve Tables, around 450 BCE, 2 of 6.” The Twelve Tables is highlighted, because the user came from it (DES-NAV-010).
  3. Up Arrow: “Start of the Roman Republic, around 509 BCE, 1 of 6.”
  4. Left Arrow: nothing happens. Left Arrow and Right Arrow don’t move within a list.
  5. Down Arrow: “Twelve Tables, around 450 BCE, 2 of 6.”
  6. Enter: “Twelve Tables, around 450 BCE. Dependencies, 2.” The user is on a moment again, and its lists work as before.

A period that is still going on. The current entry is the People’s Republic of China, and the user is on its last moment.

  1. Down Arrow: “Ongoing.” It can’t be gone to, so Enter does nothing.

Nowhere earlier to go. The current entry is the electric battery, which has no dependencies.

  1. Left Arrow: the bump sound plays, and the user stays where they are.

Screen reader integration

ID Design Status Satisfies
DES-SR-006 The current entry, a moment or a period, is shown as a card made of standard controls, so the screen reader’s own commands work on every part of it, including “read current line” (NVDA+Up Arrow). In order:
1. A heading with the entry’s name.
2. Summary: a read-only text box with three lines: the name, the date or dates, and the location (for a moment) or “Period” or “Period, still going on”.
3. Description: a read-only text box.
4. A tab control with one tab per list, showing its count, for example “Dependencies (2)”.
5. A list box of the active list’s entries, with focus on the highlighted entry.
Tab and Shift+Tab move between the parts in this order: summary, description, list, tabs. The list comes before the tabs because it is used far more, although the tabs are shown above it. When a new entry is shown, the caret in each text box starts at the top line. Within one entry, each box keeps wherever the user left the caret.		 Agreed REQ-ACC-004, REQ-ACC-007, REQ-ACC-014, REQ-ACC-016
DES-SR-002 In VoiceOver, Quick Nav must be off for the arrow keys to reach the application. Keyboard help says so. Proposed REQ-ACC-003, REQ-ACC-008
DES-SR-004 Focus is moved after the key that caused it has finished, so the screen reader handles the two separately. Proposed REQ-ACC-011
DES-SR-007 A new list box is built each time the entry or the tab changes, so the screen reader sees focus enter a new list and reads its label. The old list box stays until focus has moved into the new one. Otherwise focus would drop to the page for a moment, and the screen reader would announce the document and its landmarks again. Agreed REQ-ANN-007, REQ-ACC-015

Visual presentation

ID Design Status Satisfies
DES-VIEW-001 The current entry is centred. Its dependencies are drawn to the left and the entries it enabled to the right. The highlighted entry is marked.
In Step 0D, the whole sample is drawn, and the drawing scrolls to put the current entry in the middle. The current entry has a blue outline, the highlighted entry in the list an orange one, and the current moment’s links are drawn in blue.		 Proposed REQ-VIEW-001, REQ-VIEW-002, REQ-VIEW-006
DES-VIEW-002 Moments are drawn as dots. Periods are drawn as horizontal bars from their start moment to their end moment. The moments in between are drawn as labelled marks along the bar. Smaller periods are drawn as thinner bars inside it. (Proposed)
A period that is still going on is drawn with a jagged right-hand edge at today’s date. (Agreed)		 Agreed in part REQ-VIEW-011, REQ-VIEW-012
DES-VIEW-003 A dependency arrow runs from one moment to another (DES-REL-006). Where a moment is part of a period, the arrow starts or ends at its mark on the period’s bar. Proposed REQ-VIEW-011, REQ-REL-011
DES-VIEW-004 Uncertain dates are drawn with soft, faded edges spanning their range of possible times (DES-DATE-003). Exact dates are drawn with sharp edges. Proposed REQ-VIEW-011, REQ-DATA-005
DES-VIEW-005 Three ways of spacing entries along the time axis are to be tried in an experiment, and the best kept, or offered as a choice:
• Linear time, where distance is proportional to the years between entries.
• Compressed (logarithmic) time, which gives recent centuries more room.
• Time slots, where each entry has its own column in date order, however far apart the dates are.
Built in Step 0D. Linear time is kept (DEC-53). Compressed time and time slots are dropped. In linear time, each moment starts in the row the layered layout (DES-VIEW-010) gives it, and moves to the nearest free row if its box would overlap another. Links are smooth curves, and can pass behind other boxes. Deep history and the crowded recent centuries (REQ-VIEW-005) are left to zoom (DES-VIEW-007).		 Agreed REQ-VIEW-005
DES-VIEW-006 By default, only the neighbourhood of the current entry is drawn, a few steps in each direction. An option draws its whole ancestry. Proposed REQ-VIEW-005, REQ-NFR-002
DES-VIEW-007 Horizontal and vertical zoom are independent. They are controlled by the mouse wheel with modifier keys, by pinch gestures, and by on-screen buttons. Proposed REQ-VIEW-003
DES-VIEW-008 Clicking an entry makes it current, and updates the navigator to match. Built in Step 0D: clicking a moment’s box or a period’s bar goes there, and the move is recorded in the path, so Backspace comes back. Proposed REQ-VIEW-009
DES-VIEW-010 Entries are laid out with a layered graph drawing method, which places entries to reduce crossing links and routes links around boxes rather than through them. A library such as ELK (elkjs) is a candidate, to be judged in the experiment.
Built in Step 0D with elkjs. Moments from an earlier year always go in an earlier column, so time still runs left to right, but distance shows only order. Links are drawn in straight segments.		 Proposed REQ-VIEW-001, REQ-VIEW-013
DES-VIEW-011 A drop-down list called Layout, below the card, switches the visual view between two layouts: Linear time (DES-VIEW-005) and Layered (DES-VIEW-010). Linear time is the default. A note under it says how the chosen layout spaces the moments. The choice is kept in the page address, for example ?layout=layered, so a link can open one layout. Agreed REQ-VIEW-014, REQ-VIEW-013
DES-VIEW-012 The drawing is hidden from screen readers and is not in the Tab order, because it shows nothing that the card doesn’t. A short paragraph above it says so. Proposed REQ-ACC-001, REQ-ACC-015
DES-VIEW-009 A line marks today’s date. Anything dated after it is planned, and is drawn with a dashed outline. Agreed REQ-DATA-014

Search and filtering

ID Design Status Satisfies
DES-FIND-001 Results update after a short pause in typing. Search matches names, alternative names and descriptions, and tolerates small spelling mistakes. The result count is announced without interrupting. Proposed REQ-FIND-001, REQ-FIND-004, REQ-FIND-005
DES-FIND-002 Choosing a result makes it current and moves focus to the navigator. Proposed REQ-FIND-006
DES-FIND-003 Tags are a list of checkboxes, with an any or all choice. The date range accepts BCE and CE. Filters apply to search results, lists and the visual view. Proposed REQ-FIND-002, REQ-FIND-003, REQ-FIND-007, REQ-FIND-008
DES-FIND-004 The index is a dialog listing every entry the user can go to, in alphabetical order, as “Name, date”. It is opened with slash (/) from anywhere in the card, or with the Index button on the card. Focus starts in a search box. Each word typed must appear in an entry’s name or description, ignoring capitals and accents, and name matches come first. The number of entries is announced after a short pause in typing. Down Arrow moves from the search box into the list, and Up Arrow on the first entry goes back. Page Up and Page Down move ten entries. Enter goes to the entry, which becomes current and is recorded in the path, and focus returns to the card. Enter in the search box goes to the first entry. Escape closes the index without moving.
Example: typing “chat” leaves “ChatGPT, 2022”, and Enter goes to it. Spelling mistakes are not yet tolerated (DES-FIND-001).		 Agreed in part REQ-FIND-001, REQ-FIND-005, REQ-FIND-006, REQ-FIND-009

Wikidata import

ID Design Status Satisfies
DES-IMP-001 The import is a command-line script that the developer runs. It writes a seed file and a report. The seed file is then loaded into the database. Proposed REQ-CONT-001
DES-IMP-002 The seed set is gathered by starting from the working examples, called roots, and following dependency links backwards in time, one step at a time, until there are no more or there are 200 entries. The roots are the original iPhone (Q621427) and ChatGPT (Q115564437) (DEC-58). Q2766 is the whole iPhone series, which has no date. The walk skips an item that certainly came after every entry that links to it, such as GPT-5, which ChatGPT “uses”, and the report lists it. The curation file can add more starting points, and the periods that gathered entries are part of are added at the end. The page opens at the first root. Proposed REQ-CONT-007
DES-IMP-003 Each imported relationship records the Wikidata property it came from. The report shows how many links each property contributed. Proposed REQ-CONT-008, REQ-CONT-011
DES-IMP-004 A curation file, data/curation.json, adds, removes and corrects entries and links. It is applied on every import. It names every item by its Wikidata ID, and can give: the root, the most entries allowed, extra starting points, items to exclude, corrections to an item’s ID, name, description or dates, links to add or remove, and members to add to a period. The report notes corrections that had no effect, such as an added link that Wikidata now has. Proposed REQ-CONT-010
DES-IMP-005 The Wikidata properties used, checked against real data in Step 0C (DEC-54).
• Dependencies: “uses” (P2283), “based on” (P144), “depends on software” (P1547) and “has cause” (P828). Also these hardware properties, which the original iPhone uses for its parts: “source of energy” (P618), “display technology” (P5307), “sensors” (P9192), “input device” (P479), “connector” (P2935), “operating system” (P306) and “CPU” (P880). “Has part(s)” (P527) on a moment gives its parts as dependencies.
• Read backwards: “has effect” (P1542) and “immediate cause of” (P1536), found through the Wikidata query service.
• Containment: “part of” (P361), and on a period, “has part(s)” (P527) and “significant event” (P793).
• Moment dates, in this order: “time of discovery or invention” (P575), “inception” (P571), “point in time” (P585), “publication date” (P577) and “launch date” (P619), which spaceflights use.
• Periods: an item with a “start time” (P580) or “end time” (P582) is a period. The start is P580 or “inception” (P571), and the end is P582 or “dissolved, abolished or demolished date” (P576). A period with no end date is taken to be still going on.
• Approximate dates: the “sourcing circumstances” qualifier (P1480) with the value “circa”.
• Location: “location” (P276), else “country of origin” (P495), else “country” (P17).
• Tags: the labels of “instance of” (P31) and “subclass of” (P279), up to three.
• Names: the English label, or else the label for all languages (“mul”), which many items, such as the original iPhone, now use instead. Preferred statements are used when there are any, and deprecated ones never.		 Proposed REQ-CONT-008, REQ-DATA-009
DES-IMP-006 Date precision is taken directly from Wikidata’s own precision codes: 11 is day, 10 is month, 9 is year, 8 is decade, 7 is century, 6 is millennium, and lower codes are deeper time. Proposed REQ-DATA-005
DES-IMP-007 The report lists missing dates, broken predates rules, entries that fall outside their period, and circular dependencies. Problem links are left out of the seed file. Proposed REQ-CONT-011, REQ-REL-007
DES-IMP-009 An item with no usable date is left out, and the walk doesn’t go through it. It is listed in the report with how many entries depend on it. Where it matters, Claude looks up a first date in the item’s English Wikipedia article, and the curation file gives that date with a note naming the article (DEC-56). Where the article states no clear first date, the item stays out. Example: the microphone is dated 1876 from Wikipedia, but the accelerometer has no clear date, so it is left out. Agreed REQ-CONT-011
DES-IMP-010 Each Wikidata answer is kept in a cache folder, .cache/wikidata, which isn’t in the repository. Running the import again uses the cache and gives the same result. “npm run import – –refresh” asks Wikidata afresh. Each moment and period in the seed file keeps its Wikidata ID, and each dependency the property it came from. Proposed REQ-CONT-004, REQ-CONT-008
DES-IMP-011 Until the seed set has been reviewed, the page opens the hand-made sample. Adding ?data=seed to the address opens the seed set instead, starting at the root. Proposed REQ-CONT-001
DES-IMP-012 An item’s name is its English label, else its label for all languages, else the title of its English Wikipedia article. An item with none of these is left out, and the report lists it. Agreed REQ-DATA-001
DES-IMP-008 Each period starts and ends with real moments (DES-DATA-008). The import fetches the events (“significant event”, P793) and parts (“has part(s)”, P527) a period lists, and keeps the moments among them that could have happened on its start or end date. The start moment is the earliest member that could have happened on the start date, and the end moment the latest that could have happened on the end date. A member that is itself a period offers its own start or end moment. The curation file can name the start and end moments instead. An item with no real start moment, or no real end moment when it has an end date, is imported as a moment at its start date, and the report lists it. A Wikidata dependency that points at a whole period is attached to its start moment (DES-REL-007), and listed in the report.
Example: the curation file gives World War I’s start as Austria-Hungary’s declaration of war on Serbia, and its end as the Armistice of Compiègne. The Reykjavík Summit has no events in Wikidata, so it is a moment.		 Agreed in part REQ-CONT-001, REQ-REL-011, REQ-DATA-002

Non-functional design

This section holds design decisions that aren’t about behaviour: the technology choices and the coding standards.

Technology

ID Design Status Satisfies
DES-TECH-001 TypeScript throughout: front end, server and import tool. Agreed (delegated) REQ-CODE-002
DES-TECH-002 Cloudflare D1, Cloudflare’s SQL database, which is based on SQLite. Agreed REQ-TECH-002
DES-TECH-003 A Cloudflare Worker serves both the front end and a read-only JSON API. Proposed REQ-TECH-001
DES-TECH-004 The front end is plain TypeScript classes with no UI framework, built with Vite. This gives full control over focus and announcements. Proposed REQ-ACC-001, REQ-CODE-002
DES-TECH-005 The visual view is drawn in SVG. The D3 library is used only for time scales and zooming. Proposed (delegated) REQ-VIEW-001, REQ-VIEW-003
DES-TECH-006 The code and these documents are kept in a public git repository on GitHub. Agreed REQ-CODE-001

Coding standards

ID Design Status Satisfies
DES-CODE-001 The code is object-oriented, built from classes with clear public interfaces. A class doesn’t mix responsibilities where that can sensibly be avoided. Agreed REQ-CODE-002
DES-CODE-002 One class per file, and the file is named after the class. There is no fixed limit on file size: a file is as large as its single responsibility needs. Small types used only by that class, such as an enumeration, may sit in the same file. Agreed REQ-CODE-002
DES-CODE-003 The core logic (the model, dates, graph rules, navigation state and announcement wording) doesn’t depend on the browser, the user interface or Cloudflare. Proposed REQ-CODE-002
DES-CODE-004 Dependencies between parts of the code point in one direction only. The user interface, the server and the import tool all depend on the core. The core depends on none of them. Proposed REQ-CODE-002
DES-CODE-005 Each core class has unit tests. Proposed REQ-CODE-002
DES-CODE-006 An architecture document lists every module and its responsibility. Proposed REQ-CODE-002
